
1. Objetivo del ProyectoModernizar el acceso a DatCorr integrando el inicio de sesión con Google. Esto reducirá incidencias por contraseñas olvidadas y mejorará la experiencia de usuario, manteniendo intactos el sistema de permisos, niveles de seguridad, auditoría y roles actuales.2. Arquitectura de la Solución (Flujo UI Alternativo)Frontend (React/Vite): El usuario hace clic en "Ingresar con Google". Google despliega un selector de cuentas seguro sobre la interfaz. El frontend recibe un token de identidad cifrado (id_token) y lo envía al backend.Backend (FastAPI): Verifica la firma del token directamente con los servidores de Google.Si el usuario existe: Actualiza su información y emite un JWT nativo de DatCorr.Si el usuario es nuevo: Frena el acceso automático y envía sus datos a la sección de "Altas Pendientes" para que un administrador autorice su rol y nivel.3. Plan de Ejecución y Cronograma (Estimado: 2 Semanas)📅 Fase 1: Configuración de Entornos e Infraestructura (Días 1-2)Google Cloud Console: Crear el proyecto institucional datcorr-prod. Configurar las credenciales OAuth 2.0 (Tipo: Aplicación Web), definiendo los orígenes permitidos de desarrollo (localhost) y producción (https://tudominio.com).Variables de Entorno: Registrar las credenciales de forma segura (GOOGLE_CLIENT_ID en frontend/backend y GOOGLE_CLIENT_SECRET únicamente en el servidor backend).🗄️ Fase 2: Base de Datos y Modelos (Días 3-4)Migración de Base de Datos: Ejecutar script en PostgreSQL para incorporar los nuevos campos al modelo de Usuario:google_id (Identificador único de Google)auth_provider (Por defecto 'local', almacena 'google' si corresponde)Campos complementarios: google_name, google_picture y actualizado_en.⚙️ Fase 3: Desarrollo del Backend - FastAPI (Días 5-7)Dependencias: Incorporar la librería oficial google-auth.Endpoints: Crear la ruta POST /auth/google-login. Implementar la lógica de decodificación y verificación asimétrica del token.Control de Negocio: Programar la validación email_verified: true. Implementar el desvío a aprobación de administradores para correos no registrados.Auditoría: Agregar eventos específicos a la tabla de logs: GOOGLE_LOGIN_SUCCESS, GOOGLE_LOGIN_FAILED, GOOGLE_LINK y GOOGLE_UNLINK.💻 Fase 4: Desarrollo del Frontend - React (Días 8-10)Librerías: Instalar @react-oauth/google para el manejo óptimo de componentes visuales.Interfaz de Login: Envolver la aplicación en el proveedor de Google e integrar el botón oficial estandarizado justo debajo del formulario tradicional.Interfaz de Perfil: Diseñar las opciones en el perfil de usuario para permitir "Vincular" o "Desvincular" la cuenta de Google de forma manual.🧪 Fase 5: QA, Control de Riesgos y Despliegue (Días 11-12)Pruebas de Casos Extremos: Validar intentos de duplicidad de emails, bloqueos de cuenta activos en el sistema y control de inyección de tokens inválidos.Despliegue a Producción: Forzar uso exclusivo de HTTPS (requerido por Google) y activar la flag de seguridad COOKIE_SECURE=true para el manejo del ciclo de vida de las sesiones.4. Mitigación de Riesgos y SeguridadSeguridad Absoluta del Secreto: El GOOGLE_CLIENT_SECRET jamás se expondrá en el código del cliente web (Vite).Ataques de Fuerza Bruta: El nuevo endpoint de Google heredará el Rate Limiting estricto del sistema actual (máximo 5 intentos por IP en 5 minutos).Independencia Operativa: Si los servicios de Google sufren una caída global, los usuarios con contraseñas locales creadas previamente podrán seguir operando con normalidad.
